# 自适应单/多智能体：完整接入设计

更新：2026-09-11。执行顺序以 [PROJECT_MASTER_PLAN.md](PROJECT_MASTER_PLAN.md) 为准，本文对应 D1/D2/D4/D5/D6/D8/D9。

旧版 S8 fixed/fanout 首版及“逐模式评测后才扩展”排期已经替换；原稿保存于 [历史 S8 计划](history/DYNAMIC_ORCHESTRATION_PLAN_2026-09-10.md)。本文件描述目标实现，不把已有初版当成全部功能完成。

## 1. 产品决定

- 调度是主流程：用户提供目标，系统选择最适合的执行方式、按计划执行并交付。
- 默认 auto，过程可查但默认收起；可手动指定方式或开启“只看计划”。
- 只有超授权预算或缺失无法合理默认的关键条件时必须等待；用户主动启用计划确认时尊重该选择。
- 最终支持 single/fixed/manager_worker/fanout/dynamic_team/debate 与有界嵌套派工。fixed/fanout 是开发中间步骤，不是最终范围。
- 全部方式在 D 阶段完成；Q 阶段比较收益与校准自动选型，不能用尚无优势证明为由无限推迟已承诺方式。

## 2. 一条共享执行路径

统一请求 → 根任务/会话 → 能力与范围检查 → 调度方案 → 程序校验 → 依赖调度/派工 → 结构化成果 → 按工作类型交付检查 → 成果/依据/方式/费用/等级。

所有角色和方式共用 Runtime、模型/工具网关、根预算、状态、来源与产物体系。子运行可以有局部状态和上下文，不能另起不受根预算约束的任务。

简单计算不跑报告全链；研究成果仍必须通过证据与支持关系检查。任何方式均不能因为叫“debate”或“dynamic_team”而绕过交付要求。

## 3. 契约要求（D1、D4、D5）

| 对象 | 必需内容 |
|---|---|
| 任务请求 | 目标、输出要求、文本/文件/URL、网络授权、会话/原稿、显式方式、模型档案、调用/Token/时间/费用限制 |
| 执行方案 | schema_version、plan_id/version、root_job_id、方式、理由、能力需求、复杂度信号、任务清单、预计开销、降级方案 |
| 子任务 | child_id、parent_id、role、description、depends_on、输入 ArtifactRef/EvidenceRef、covers_sections、输出约定、预算份额、权限、状态 |
| 子成果 | status、摘要、artifact_refs、evidence_refs、来源版本、conflicts/gaps、失败原因、用量和完成时间 |
| 证据引用 | root 内稳定 ID、source_id/version、原文摘录、页码/段落/偏移、事实/推断/未知属性 |
| 过程事件 | 根/子/计划版本、阶段、动作、真实状态、已知与未知费用，不保存密钥和认证头 |

具体字段名由 D1 实现时沿用现有结构决定；版本迁移需说明兼容性。计划只接收目标、约束和资料概况，必要资料由执行阶段按授权读取，来源文字不能成为系统指令。

校验包括：未知角色/模式、重复 ID、空任务、循环/未知依赖、缺章节覆盖、不可用工具、预算/数量/深度越界。解析失败有限重出；真实传输失败按未知用量规则处理，不能当无消耗格式错误反复重试。

## 4. 六种执行方式（D6）

| 步骤 | 方式 | 必须真正发生的行为 |
|---|---|---|
| D6-01 | single | 一个执行体按需用工具/材料完成简单目标；接受同一预算和交付规则 |
| D6-02 | fixed | 复用既有固定阶段，不丢用户文件、模型或限制 |
| D6-03 | manager_worker | 统筹者按任务依赖安排角色，验收阶段成果后推进 |
| D6-04 | fanout | 独立子任务真实有界并发，汇总时处理分支失败与证据来源 |
| D6-05 | dynamic_team | 根据新缺口有限重规划/增减分工，保存历史和失效关系 |
| D6-06 | debate | 正反论据均有出处，审查支持关系与争议，不能以投票判事实 |
| D6-07 | 嵌套派工 | 子智能体在继承权限和份额内派二层任务，不另建预算根 |
| D6-08 | 统一注册与降级 | 各方式可被统一入口选择；切换方式不丢材料或重置额度 |

Handoff 负责前置成果交接；Blackboard 是受控共享成果区；Generator–Critic 复用生成/检查/有限修改机制。避免每种模式各写一套存储和控制逻辑。

## 5. 预算、并发与派生护栏（D2 必须先完成）

可派工额度 = 根剩余 − 在途预留 − 最终交付预留。单子任务初始上限取可派工池 40%，各份额之和不得超过池。预留必须原子化，网络等待期间不持全根请求锁；成功结算，失败/超时保留未知项。

调度、重规划、压缩、模型审校、搜索、工具及每次重试均记根账本。未知成本不记零；不能因失败重试、恢复或更换方式重新获取一份预算。

初始边界沿用总计划：深度 ≤2、派生总数 ≤12（嵌套合计）、并发 ≤3；并发的功能验证证明请求实际重叠即可，性能对比留 Q3。禁止同题无进展反复派生。

用户已选择默认预算按同等规模最省/最贵典型成本中点确定；D 阶段使用可见配置估值，实际数值在 Q3 校准。用户预算永远优先，模型不能扩大。

## 6. 资料、证据与失败语义

- 真实搜索与正文读取在 D3 接通，不能推迟到整体试用才做。仅有 mock provider 不算完成。
- 子报告是分析产物；汇总时保留原始 source/evidence 映射，不重新将模型文字标为原始事实。
- 失败先判断可否重试及剩余额度；允许的重试/重规划次数有限。部分失败记录缺口，并进入最终交付判断，不能只置 degraded=true 就放行成品。
- 来源撤回、目标变更或计划版本变化时，失效标记传递到依赖成果，旧审批也需重新核验。
- 根取消传播所有子任务；已经发出的请求可能仍产生费用，界面区分取消请求与已停止。
- 恢复优先复用已提交来源/子成果/阶段；结果未知的外部调用不得自动当未执行重放。不能承诺无条件不重复付费。

## 7. 入口和记录

D9 将 Web/CLI 接到同一应用服务。显式配置必须贯穿调度与执行，特别是 files/profile/max_output_tokens/allow_network/零限额。只看计划不得发起执行器。

默认结果页展示成果、所选方式和一句理由、总用量/已知费用/未知项、等级与局限；计划、子任务树、调用记录是可展开详情。计划确认和关键条件补问使用持久待处理状态。
