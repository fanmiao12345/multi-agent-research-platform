# 资料整理与研究写作：首个落地场景实施说明

更新：2026-09-11。本文是场景专项说明，完整项目目标与唯一排期见 [PROJECT_MASTER_PLAN.md](PROJECT_MASTER_PLAN.md)。

旧版固定写作主线与逐批优化安排已替换；原文保存在 [历史计划](history/PRACTICAL_RESEARCH_WRITING_PLAN_2026-09-10.md)，仅用于追溯，不再指挥当前开发。

## 1. 场景在整体项目中的位置

个人 AI 智能体系统根据目标自行规划、调用工具、分工、检查并交付。资料整理与研究写作是第一类完整业务场景，不是对系统整体目标的缩减。

固定研究链保留为一种可选方式和共享的成稿/审校能力。简单资料问答可以由 single 完成，多个独立问题可使用 fanout，有依赖的角色协作使用 manager_worker，执行中需要调整的任务可使用 dynamic_team，争议分析可使用 debate。全部方式在功能开发阶段实现，之后再统一比较效果。

## 2. 用户任务与交付

| 任务 | 输入 | 目标交付 |
|---|---|---|
| 已有资料整理 | 文本/文件/链接、整理要求 | 资料目录、主题摘要、重复项、冲突和缺口，带原文定位 |
| 主题研究 | 主题、网络策略、可选资料、预算 | 自主获取的原文、分析与带引用报告、局限 |
| 比较或核查 | 对象/说法、已有资料、允许补充范围 | 逐项比较/核查结果，区分支持、反证、无法判断 |
| 报告写作 | 目标读者、结构/长度等要求、资料 | 依据材料成稿、审校记录、来源与证据 |
| 追问改稿或更新 | 已有任务/原稿、新要求/新来源 | 新版本、变更与引用更新，旧版本保留 |

正常工作由系统自动推进。仅超授权预算、关键业务条件缺失，或用户主动开启“先看计划”时等待用户处理；不是每个子任务都询问。

## 3. 材料与数据规则

- 支持范围：文本、TXT/Markdown、HTTP(S) 链接、Bing 搜索结果页抓取（bing_scrape，用户指定先行；百度 API 保留待 Key）、文本型 PDF。PDF 页码进入引用定位；OCR/DOCX/复杂表格是扩展，不列本轮必做。
- 仅给定资料时不自动搜索；允许联网且材料不足时执行有界检索和正文读取。
- 搜索摘要只用于候选筛选。失败网页、模拟结果不能当作已读取的真实证据。
- 来源保存原始/最终地址、正文、哈希、获取时间与版本；发布日期未知就写 unknown。
- 根/子任务共享来源与证据引用关系。模型生成的子报告属于分析产物，不能升级为独立原始证据。
- 冲突保留不同来源归属；同文转载不重复增加证据数量。
- 初始上限沿用每任务 20 来源、单来源正文 2MB/合计 10MB；网络下载与 PDF 解析另有资源限制。数值优化安排在 Q3。

## 4. 开发顺序与总计划对应

| 场景工作 | 总计划步骤 | 功能完成表现 |
|---|---|---|
| 统一输入及会话/预算 | D1、D2 | 文件、网络、模型、限制不因入口或派工丢失 |
| 真实搜索、网页与 PDF | D3-01～05 | 只给主题能获得实际资料；失败来源清楚可见 |
| 上下文与成果交接 | D4 | 下游实际获得必要材料，能按引用读取全文 |
| 选型及六方式执行 | D5、D6 | 全部方式接入统一入口与根账本，不先比质量再开发 |
| 证据、成稿、补做与改稿 | D7 | 有限补搜/修订，引用可追原文，版本可查看 |
| 取消、恢复和待输入 | D8 | 根/子任务按已保存状态继续，未知操作不静默重放 |
| 用户界面及导出 | D9 | 一次输入后查看成果和依据，过程默认收起 |
| 装配与功能冻结 | D10 | 本场景与整个系统同时达到功能完整门槛 |
| 整体测试/真实质量/优化/试用 | Q1～Q4 | D 全部完成后执行，不能在固定链开发中反复调分 |

## 5. 产品运行中的检查

提取证据 → 素材/冲突/缺口 → 按任务形成提纲或答案 → 成稿 → 程序与模型检查 → 必要时有限补做。

这是产品必须具备的行为，D 阶段实现；开发人员用真实批次反复调整提示词属于 Q 阶段。两者不可混淆。

成品、草稿、无法完成与失败/取消/中断分别记录。模型内部 accepted 不等于独立业务验收。引用存在只证明可定位，语义支持还需审校与整体评估。
