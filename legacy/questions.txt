Agent MVP 练习题目
==================

单次问答（python agent.py -q "问题"）：
  1. 现在几点了？                      -> 应调用 get_time
  2. 帮我算一下 12345 * 6789 等于多少？ -> 应调用 calculator
  3. 计算 (15 + 3.5) * 4 / 2 的结果    -> 括号运算
  4. sqrt(2) 的值是多少？              -> 数学函数
  5. 上海今天天气怎么样？              -> 应调用 get_weather（模拟数据）
  6. 帮我记住：周三下午三点开产品评审会 -> 应调用 save_memo
  7. 不要用工具，直接回答：1+1 等于几  -> 观察模型是否真的忍住不用工具（防「工具依赖症」）

连续对话（python agent.py 进入交互模式）：
  8. 依次问：「记住我喜欢喝美式咖啡」->「我记过什么？」-> 问天气
     -> 观察：对话历史被保留，模型记得上下文
  9. 问一个需要两步的任务，如：
     「帮我把 25 的平方根算出来，然后记住这个结果」
     -> 观察模型是否连续调用两个不同工具（多步规划）
 10. 问一个超出工具能力的问题（如「帮我订一张机票」）
     -> 观察模型如何诚实地说自己做不到（而不是编造）

进阶（真模型模式下再试）：
 11. 让模型连续追问工具结果的场景，观察 ReAct 循环何时收敛、何时需要你设的 MAX_ROUNDS
 12. 打开 last_transcript.json，对照 README 中的流程图，把每一轮消息读一遍，
     搞清楚 messages 里 system / user / assistant(tool_calls) / tool 四种角色的作用

技能（skill）练习：
 13. 直接运行 python agent.py（不带 --skill），问：
     「我想写一篇公众号文章，主题是坚持健身一年我收获了什么」
     -> 观察：横幅显示「技能: 自动路由」，控制台出现 [技能路由] 命中提示，
       小智回答开头声明使用了哪个技能（真实模型模式）
 14. 同一次会话里接着问「现在几点了？」
     -> 观察：不命中任何技能，路由器直接放行，回答不掺技能内容
 15. python agent.py -q "把'远程办公的利与弊'梳理成一篇报告的大纲"（单次，自动路由）
 16. python agent.py --skill writing-outline   # 强制指定（关闭自动路由）
 17. 自己改 skills/writing-outline.md（比如把步骤改成 5 步），再跑 13，对比差异
 18. 在 skills/ 下新建自己的技能（如 code-review.md），description 写清楚适用场景，
     然后直接提问测试路由是否命中；想离线模拟命中，就在 frontmatter 里补 keywords

两级路由与人工兜底练习（技能多起来之后的核心玩法）：
 22. 观察命中理由：python agent.py -q "帮我想一篇关于远程办公的文章大纲"
     -> 控制台应打印 [技能路由] ……（理由: 命中"文章、大纲"），
     对比问「现在几点了？」——召回为空，连精排调用都不会发生
 23. 误命中排查：给 writing-outline 的 avoid_when 加一条「用户想润色文字」，然后问
     「帮我把这段文字润色一下」——观察它不再命中（负向检索扣分）
 24. /use 命令：交互模式输入 /use 查看状态；/use writing-outline 手动指定后
     问天气问题也会加载写作技能（手动 = 你说用就用）；/use off 恢复自动
 25. 会话延续：一次会话里先问写作问题（命中注入 1 次），再问
     「那帮我把开头改得更有趣」——如果命中写作技能，控制台应显示
     「已在本会话生效，沿用（不重复注入）」
 26. 造 8~10 个假技能（复制几个 .md 改名字）验证两级路由：控制台横幅显示
     「现有 N 个技能」，但精排提示词里永远只出现 top5 候选

多智能体流水线练习：
 27. python multi.py                        # 向导模式，主题随便给一个
     -> 观察 4 个角色依次登场：研究员调用 web_search 的日志、每棒输出落盘
 28. python multi.py "深空探测的意义" --kind 研究报告 --words 2000 --extra 要数据
     -> 检查 research_output/ 时间戳目录：原始资料里的【事实】是否都带来源网址；
        终稿的「参考来源」是否与素材包一致（审校就是干这个的）
 29. 断网跑一次 python multi.py "某主题" --force-mock
     -> 研究员阶段应看到 web_search 如实返回失败说明，而不是编造资料
 30. 把 fetch_page 换成抓 http://127.0.0.1:3080/ 试试 -> 应被安全策略拒绝（SSRF 防护）
 31. 对比：同一主题分别用 python agent.py（单智能体：想到哪问到哪）和
     python multi.py（多智能体：流水线分工）跑，体会两种架构的差别与适用场景

角色技能包练习：
 32. 依次用五句触发语体验自动路由（真实模型下观察命中理由与回答开头的技能声明）：
     「帮我梳理一篇关于…的文章思路」（writing-outline）/
     「帮我调研一下…的现状，查点资料」（deep-research）/
     「把这些资料整理成素材包」（material-organizer）/
     「根据素材写一篇完整的…」（article-writer）/
     「帮我审一遍这篇稿子」（review-editor）
 33. 边界测试：对 article-writer 说「我只想要大纲」、对 writing-outline 说
     「素材都齐了直接写全文」——观察两个技能如何互相甩锅/指路（avoid_when 起作用）
 34. 打开 multi.py 里四个角色的 system prompt 与 skills/ 里同名技能对比：
     流水线版是「任务说明书」，技能版是「交互教练」，两者方法论一致
 35. /skills 查看 5 个技能；再自己写第 6 个技能，注意 intents/avoid_when 的
     措辞要与现有技能错开，避免路由互抢

主智能体（master.py）练习：
 36. python master.py "现在几点了？" --force-mock      -> 难度评估走 SINGLE
 37. python master.py "帮我调研一下深海采矿，写一篇公众号文章" --force-mock
     -> 观察主控节奏：1 次评估 → 4 次委派（含子智能体日志）→ 每棒 1 次验收
 38. python master.py --force-mock（交互）分别问简单任务与复杂任务，
     观察 MODE 自动切换；再问一句明显要返工的话（如"资料要有权威来源，核对清楚"）
     看主控是否触发 REWORK/ADD 分支
 39. 对照三个入口的层级：agent.py=单兵；multi.py=固定流水线（无主控）；
     master.py=主控 + 可伸缩（难度路由）。同一任务分别跑三者，比较节奏与产出

协作模式落地练习：
 40. 热插拔角色：复制 roles/editor.md 改名 critical-reviewer.md（改 title/description），
     让主智能体跑 multi 时看它能否被 STEPS 选中（真实模型下观察组队变化）
 41. Fan-out：python master.py "帮我调研一下深海采矿的政策、技术与环境影响三方面，
     写篇报告" --force-multi（真实模型）
     -> 主控应打印 Fan-out 拆题与并行日志；工作区里出现 research_sub1~3.md 与
        01_researcher_combined.md；state.json 里能看到每步验收结论
 42. Handoff：打开 master 多智能体运行目录里的 02_organizer.md 对应的委派（看
     last 工作区），核对它开头是否有【交接卡】说明输入来自哪个文件、验收状态
 43. 自己加一个新角色（比如 fact-checker，无工具、default 预算），写清人设后
     跑 master.py 多任务，观察注册表自动纳入角色清单（roles.py list_roles）

可观测性练习：
 44. 加 --quiet 跑同一问题对比：默认模式有 [第1轮]/[技能路由] 等详情行，
     quiet 只剩问答与 [运行摘要]；摘要里的 tokens 在真实模型下会显示入/出数字
     （Mock 显示"未知"）——这是 A3 的成果，也是以后省钱优化的读数表

热插拔练习（体验"不改代码、不重启"）：
 19. 开一个 python agent.py 交互窗口，输入 /skills 记住当前列表；
     另开一个编辑器往 skills/ 里放一个新的 .md（带 description + keywords），
     回交互窗口输入 /skills -> 新技能已出现；直接问命中它 -> 无需重启
 20. 同上：修改 writing-outline.md 的正文（比如语气词），问一个写作问题，
     观察它按新版本回答（也可看 last_transcript.json 注入的正文是否为新内容）
 21. 同上：删掉第 19 步新建的 .md，问相同问题 -> 不再命中；再输入 /skills 确认已消失

提示：在 agent-mvp 目录下执行 python agent.py --help 查看所有参数。
