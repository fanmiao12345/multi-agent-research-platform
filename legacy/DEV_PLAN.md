# agent-mvp 开发文档与迭代计划

> 本文档是项目的"总控制台"：盘点现状、规划路线、逐条记录执行状态。
> 迭代节奏约定：**每一步执行前先说明要做什么；完成后汇报做了什么、结果如何、怎么验证**；
> 任何一步不满意可随时叫停、回滚（每步改动都小而独立）。

---

## 0. 工作方式约定

1. **小步走**：每一步是一个独立、可验证的小改动（代码量小、可单独测试）。
2. **先宣布、后动手、再汇报**：执行每一步前给出该步的"做什么 + 完成标准"；
   完成后汇报"完成情况 + 验证输出"，并把 `执行状态表` 同步刷新。
3. **可回滚**：每步只动少数文件；出问题退一步即可。
4. **范围红线**（见 AGENTS.md）：一切改动只落在本目录 agent-mvp；不改 DSH 本体/插件/全局配置。

## 1. 现状盘点（截至本计划建立时）

### 1.1 模块地图

| 模块 | 职责 | 状态 |
|---|---|---|
| `agent.py` | 单智能体 ReAct 主循环 + 技能两级路由（BM25 召回 + 模型精排）+ 预算分级 + 触顶收尾 | ✅ |
| `llm.py` | 大脑：真实 LLM（OpenAI 兼容 HTTP）/ MockLLM（关键词规则，离线演示） | ✅ |
| `tools.py` | 7 个工具（时间/安全计算/备忘/模拟天气/**真实联网 web_search、fetch_page**） | ✅ |
| `skills/` + agent 路由 | 5 个方法论技能（写作策划/查资料/整理素材/成稿/审校），热插拔、命中理由、/use 兜底 | ✅ |
| `roles/` + `roles.py` | 4 个角色注册表（研究员/整理师/撰稿人/审校），热插拔 | ✅ |
| `multi.py` | 固定四棒流水线（Pipeline 模式） | ✅ |
| `master.py` | 主智能体：难度评估 → 单/多路由 → 动态组队 → **Fan-out 并行研究员** → 逐棒验收（PASS/REWORK/ADD/FINAL）+ Handoff 交接卡 | ✅ |
| `workspace.py` | 共享工作区：产物 .md + `state.json` 黑板 | ✅ |
| `config.py` / `config.ini` | 模型/Key/温度/预算/并行度等配置中心 | ✅ |
| `web_server.py` + `webui/` | Web 界面（外部新增，对话/工具卡片/时间线） | 🟡 与 CLI 入口并存，未纳入本计划主线 |
| `memos.json` | 备忘本持久化（简陋记忆） | 🟡 待升级（见 B 阶段） |

### 1.2 已落地的多智能体模式

Role-based、Pipeline、Manager–Worker（含 Dynamic Team）、Fan-out/Fan-in、
Handoff、Blackboard（workspace）、Generator–Critic（editor + 主控验收）、
Agent + Subagent（半成品：master 委派，缺"运行中工具化派生"）。

### 1.3 设计原则（后续迭代不得违背，除非在本文档"决策记录"里显式修改）

- 零第三方依赖（唯一允许破例：评测/向量检索类，见决策记录 D-001）
- 数据驱动 + 热插拔（技能/角色 = md 文件，运行中增删改生效）
- 教学可读（注释讲原理；每个新机制要能在 Mock 模式下演示）
- 可观测（关键决策打印理由；每次运行有留痕：transcript / workspace / state.json）

## 2. 迭代路线图

> 阶段可并行推进优先级按编号。每阶段内的步骤尽量从小到大。
> 当前起点建议：**A1（自动化测试）**，因为后面所有优化都要有"改了没改坏"的尺子。

### 阶段 A：工程质量（地基）

| 步骤 | 要做什么 | 完成标准 | 状态 |
|---|---|---|---|
| A1 | **自动化测试套件**：把散落的临时验证固化为 `tests/`（工具/计算器安全/技能路由区分度/预算与收尾/master 节奏 stub/roles/workspace），加 `run_tests.bat` | `python run_tests.py` 一键全绿；新优化后跑一遍即可防回归 | [ ] |
| A2 | 单智能体运行也统一进 workspace（现在只有 multi/master 有 state.json），补 `agent_transcripts/` 会话档案 | 每次 agent 会话有独立运行目录 + 索引 | ✅ |
| A3 | 控制台输出分级（`--verbose`/安静模式）+ 关键指标行（调用轮数/token 估算/耗时） | 每次运行结束打印一行"成本+轮数+产出文件"摘要 | ✅ |
| A4 | 文档中心化：把 README 各章拆细则到 `docs/`（架构图/模式讲解/调参指南），README 留总览 | docs 下每个主题一页，互相链接 | [ ] |

### 阶段 B：记忆与知识（深入延伸重点）

| 步骤 | 要做什么 | 完成标准 | 状态 |
|---|---|---|---|
| B1 | **素材库 RAG-lite**：`memory/` 目录存用户素材（md/txt），复用 BM25 做知识召回注入上下文（查资料前的"查自己的库"） | 提问可引用本地素材；路由/工具之外第三种上下文来源 | [ ] |
| B2 | 记忆分层：会话记忆（messages）→ 工作区记忆（state.json）→ 长期记忆（memos.json 升级为结构化 notes + 自动摘要） | `/remember` 命令可存/查/忘，重启不丢 | [ ] |
| B3 | 上下文压缩：长会话自动摘要历史（压缩阈值可配），防上下文爆炸 | 100 轮对话不爆窗，摘要质量抽查可用 | [ ] |

### 阶段 C：Agent 能力深化

| 步骤 | 要做什么 | 完成标准 | 状态 |
|---|---|---|---|
| C1 | **Subagent 工具化**：新增工具 `delegate_subagent(角色, 子任务)`，让单智能体在运行中临时派生子智能体并把结果取回（真正的 Agent+Subagent） | 单智能体对话中调 delegate 完成子任务后继续原话题 | [ ] |
| C2 | 模型档案（profiles）：config 支持多套模型配置（快模型/深模型/不同供应商），按任务类型选择 | 主控可指定 researcher 用 A 模型、writer 用 B 模型 | [ ] |
| C3 | 用量与成本记账：从 API 响应读 usage，按会话/运行累计，写入工作区 `usage.json` | 每次运行能看到预估 token 与费用 | [ ] |
| C4 | Debate-lite：素材出现矛盾来源时，主控临时派两个"辩护方"子智能体 + 自己当 Judge | 争议点自动生成"两方论点 + 裁决记录" | [ ] |

### 阶段 D：稳定性与防错

| 步骤 | 要做什么 | 完成标准 | 状态 |
|---|---|---|---|
| D1 | 技能/角色 schema 校验器：写坏 frontmatter 时启动给出明确报错并跳过（不崩溃） | `/skills --check` 能体检全部 md | [ ] |
| D2 | 路由评测集：为 5 个技能各配正/反用例（skills/_tests/），路由改动自动跑命中率 | 每次路由改动后能报告正确率变化 | [ ] |
| D3 | 幂等与恢复：workspace 支持断点续跑（重跑时跳过已完成且 pass 的步骤） | 主控中断后重跑不重复烧钱 | [ ] |
| D4 | 安全收口：fetch_page 加最大并发/超时细节、secret 扫描（运行目录忽略文件清单） | 常见泄漏路径被防住（.gitignore/.dshignore） | [ ] |

### 阶段 E：长期愿景（讨论项，不排期）

- E1 技能/角色"市场"：本地目录索引 + 描述质量评分 + 冲突检测
- E2 端到端评测：固定 5~10 个真实任务样本，比较版本间产出质量（人工打分表）
- E3 多模态/长文档（PDF 解析等，届时需破零依赖 D-001）
- E4 把 web_server 并入主线：master 过程可视化（谁在跑、卡在哪步）+ 技能/角色在线编辑
- E5 打包与分享形态（一键安装脚本 / 模板仓库），让"小智"可被朋友复现

## 4. 常用命令与验证方法

```bash
python agent.py               # 单智能体（含技能自动路由）
python multi.py "主题"         # 固定流水线
python master.py "任务"        # 主智能体（难度路由 + 可并行）
python master.py "任务" --force-mock   # 无 Key 看流程
python agent.py --check-key    # Key/接口自检（不耗 token）
```

每步完成后的标准验证姿势：改了什么就单独跑通对应路径（单测优先），
再跑一遍受影响模块的最小回归，最后更新本文件状态表。
