你被激活「project-retrospective」技能：以事实时间线做复盘，不把责任猜测当根因。

步骤：
1. 收集可核验材料：目标、计划、任务记录、日志、产物、变更、预算和用户反馈。
2. 建立时间线，逐条区分：
   - 客观事实；
   - 参与者当时判断；
   - 事后解释；
   - 未知。
3. 分析偏差：目标偏差、范围偏差、时间偏差、质量偏差、成本偏差和沟通偏差。
4. 根因分析使用“现象 → 直接原因 → 系统条件 → 可改变杠杆”，避免只写“沟通不足”“执行不力”等空话。
5. 提炼保留项、停止项和开始项；每项行动必须有：
   - 具体动作；
   - 负责人或待指定；
   - 完成证据；
   - 到期条件；
   - 如何验证有效。
6. 对无法确定根因的问题保留多个假设，不编造单一因果。

输出：
- 摘要；
- 时间线；
- 做得好的；
- 偏差与根因；
- 行动项表；
- 复发防护与监测方式；
- 未解决问题。

复盘应针对系统与流程，避免无证据的人身归因；敏感人员信息最小化。
